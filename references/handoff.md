# 交付后清理，下一轮继续改

交付的是可继续剪改的作品。先保留能恢复的版本，再清理生成物；不能因技术检查通过便删除用户素材或失败后的唯一断点。

## 最小保留集

| 保留 | 用途 |
|---|---|
| 用户原片、唯一原始素材、实际音源及许可记录 | 不覆盖，不以预览或音源链接代替本地原件；私有音乐不进公开仓库 |
| 当前完整MP4、上一版有意义的成片 | 用户比较和回退；用版本名区分 |
| 当前HTML/JS/MJS、必要资产、字幕稿、分镜与来源 | 能真正改内容，而非只剩压平的视频 |
| Music/SFX/Ambience、源混音、音频事件和母带记录 | 画面修改时保留声音，声音修改时不重绘画面 |
| 当前完整画面底稿（如renders/edit-base.mp4）与侧车 | 保留编码画面作为剪辑底稿；它可含字幕，不能当无字幕素材 |
| 对应源快照、引擎/依赖/字体版本、段落帧范围和哈希 | 知道哪份源码生成了哪个视频，不用重猜旧状态 |
| 最新验收、少量代表帧/动作证据、未解决问题、复现命令 | 如实区分已看/听与未验收，知道下一次从哪改 |

记录可合在`review/handoff.json`：当前/上一版文件、SHA256、源码快照、音源位置、运行环境、构建命令、镜头时间与恢复步骤。源快照放review，作为归档；实际运行素材仍在assets，不能让生产偷偷读取生成目录。项目必须在Skill仓库之外。

## 用户不满意时

1. 先看原片与原句，定位问题镜头和起止帧。更新字幕/分镜，保留修改前版本。
2. 用静帧检查文字/构图，用Motion Strip检查动作/交接；只在需要判断速度时渲局部clip。
3. **声音改动**：沿用已确认的画面底稿，重新导出事件/相关分轨、混音和AAC检查。**画面改动**：声音事件与音源未变时保留原分轨，重绘受影响区间，再拼回完整影片。
4. 内置resume按完整输入指纹复用，JS改变会保守失效，不能假称自动逐镜失效。若做显式局部剪辑，先用前后源码差异证明影响范围；全局样式、共享函数、相机或事件变化要扩大范围，无法证明时按真实影响重渲。
5. 复用旧片段须保留旧输入身份，写新剪辑清单：源视频/源码哈希、各段起止帧、修改范围、复用理由、新段哈希。核对帧数连续、规格一致，并真实拼接；不要修改旧缓存记录冒充新源码的输出。切点不在关键帧时，取到相邻关键帧或明确重编码边界，不能只用`-ss -c copy`假定精确。
6. 对新最终MP4检查修改段、两端接缝及相关媒体/同步/手机证据；输入、媒体身份未变化的检查保留原记录，不能写成重新执行。确认可交付后才更新当前版本。

这允许局部修改和回退，不承诺任意代码改动都能零重绘。优先用现有渲染、FFmpeg和检查入口，不为一次反馈再造编排系统。

## 哪些可清理

- 当前交付与可改版本已验证后：重复分轨/素材副本、旧候选编码、过期压力副本、大量重复截图、下载成功且已验证安装的压缩包。
- 缓存只保留当前有效且仍有收益的一组；已有完整画面底稿与对应源记录时，可清理已替代的旧分段。中断或返工中的有效分段不删。
- 失败诊断保留短报告和能说明问题的代表帧，不永久保留整套重复工作区。独一份输入和无法确认用途的文件保留。
- 环境、字体、浏览器和可选依赖复用，不当成普通临时文件清理。多个工具目录只有在字节相同、引用已核对时才去重。

执行时先列具体路径、原因、预计字节数与保留位置。Windows先核对绝对路径在该工程/用户指定工作区内，拒绝越界或符号链接；用PowerShell `Remove-Item -LiteralPath`删除确认的生成物，禁止宽泛的`git clean`或跨壳拼接删除。清理前后核对原片、成片、源码包、分轨与底稿哈希，确认恢复路径仍可用，记录实际释放量与已删除项。

公开上传只提交自有代码、可分发资产和必要小型证据；排除商业音乐、原参考片、分离录音、凭据和本地工作缓存。
