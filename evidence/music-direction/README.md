## 音轨实际测到了什么

[完整分析数据](reference-analysis.json)由本轮 `analyze_music.py` 对原MP4直接解码，含源SHA、实现SHA、FFmpeg身份、2ms候选网格、局部周期、起音、每秒能量及首尾100ms包络。可用同一附件复现：

```powershell
python scripts/analyze_music.py <用户附件.mp4> --out <本地>/reference-analysis.json
```

- 频谱起音周期：56.4337 BPM（1.063194秒，相关强度0.657）与112.9507 BPM（0.5312052秒，0.6345）均强。包络独立估计最高76.2372，其后45.4526/56.3872/112.3217；结果存在节奏层级/重音歧义，不能选择一个数字冒充已听准的拍速。
- 用户约112BPM/0.534秒与候选范围相近；不证明同曲、变速或重采样。16秒滑窗的周期变化也可能只是配器/重音变化，没有确认速度变化。
- −60dBFS活动阈值首次0.018秒、末次130.0086秒；这是**完整混音**，不能分离音乐真正起点/终点。没有≥0.2秒的阈下静默候选；78–92秒只是较安静。首100ms约−7.28dBFS，末100ms约−9.33，不据此声称长淡入/淡出。
- 最强能量/密度边界约17秒，前后1秒RMS−15.86→−7.69dBFS；69/86/93秒也有明显变化。小节、强拍、乐句和高潮仍需人工核听，数据保留null/未验证，而非每四拍自动命名乐句。
- 既有最终混音测量−10.11LUFS、+3.08dBTP不是原创片目标。响度与情绪不是同一件事。

## 知识、画面和音乐的代表性交会

画面时刻为实际抽样确认的**近似区段**；音乐变化为测量；导演用途是可迁移解释，不声称读出作者意图或精确音符落点。

| 约秒 | 知识事件/画面操作 | 音乐可观察状态 | 导演启发 |
|---|---|---|---|
| 0–6 | 骰子运动与停稳，先给具体的不确定 | 混音开头即有活动，尚不能隔离配乐起点 | 先让观众预测，再引入概念；不能因“前奏”假设延迟提问 |
| 6–10 | 片名承接问题 | 附近有起音候选，但没有验证标题逐帧锚点 | 标题建立期待，不必冒充知识高潮 |
| 10–30 | 中断赌局与5:2直觉答案 | 17秒能量明显增强；17–30秒较强 | 先欠下论证，再让节奏建立向前的需要 |
| 27–40 | 骰子展开、计排列成25/27 | 30秒有密度/能量变化候选 | 稳定节奏陪伴计数，不在每个数字附提示音 |
| 56–68 | 树展开16端点，15:1回答早先争议 | 不在全轨最大响度处；56.106/55.846附近有起音 | 重要的是答案真的被算出，不是把音乐突然放大 |
| 69–92 | 城市点阵、反复抽样和曲线 | 69秒转弱，78–92较收敛，86秒再降 | 换观察尺度、让观众读图，允许音乐退后 |
| 约89–95；103–107 | 前者撒针求π，后者高尔顿板 | 93秒附近能量回升；不据此认领精准同步 | 用新实验扩展同一关系，不能只为配合高潮堆奇观 |
| 118–130 | 原骰子和片名回归 | 118秒附近有起音；没有测出长末尾淡出 | 同一对象因知识而改变意义；收束不等于一律淡出 |

邻近起音只是候选，不能用“离某帧很近”证明对象接触同步；原片没有作者声明条件。本项目原创作品用共享事件及几何条件验证，编码波形检测另列。

## 在已有作品和公共生产路径验证

《力的远近》继续使用原有84BPM、四个原创钢琴乐句和合法CC0录音；没有为迎合曲名更换音乐。[实际音轨分析](torque-analysis.json)自动最高56.06而非84，恰好展示稀疏钢琴不能盲用BPM探测。作者score的0/4/11/15拍是明确编曲结构，分别映射0/2.857143/7.857143/10.714286秒；不是机器发现的乐句。7.4–7.7秒有意退乐，揭晓共读beat11；改版前后AAC负载相同，未破坏动作声。

自动化另用2秒生成点击信号走完 **prepare→VK_SCORE sample→动画锚点/声明条件→正式produce→编码同步/媒体/手机证据**。它是公共适配路径的技术回归，不是新增主题影片或专业音乐试听。真实外部商业曲目整片、平台后添加的实际对齐、自然循环和主观音乐感染力尚未验收。

分析不在逐帧运行；改文件/速度/注释/实现会失效，损坏音源不覆盖旧分析。加载器拒绝配置由embed变original/platform-only后沿用旧计划，或音源换字节后直接render。细节与最小调用见[音乐导演](../../references/music-direction.md)。

配置过期负例也做了移除校验→恢复校验的实际红绿验证：无config SHA检查时，embed改original未在初始化失败；恢复后original/platform-only两种修改及音源替换均被拒绝。测试日志随本目录归档。该机制不验证真实授权，只防止声明改变后继续错误使用旧计划。
